### Protocol reminder

Two EP1 packets per LED update:
- **Packet A** `{0x0c, 0x00, data[0..30]}` — pad rubbers (slots 0–15) + scene-row (slots 16–29)
- **Packet B** `{0x0c, 0x1e, data[0..32]}` — group buttons, SA1–SA8, Note Repeat, etc.

## Remaining open issue: TransportRight LED slot unknown

**What we know:**
- logical[27] = TransportRight (confirmed from targeted transport learn 2026-04-13)
- Before this session logical[27] was passthrough in B-pkt → was driving Note Repeat hardware LED (wrong)
- logical[27] is now **suppressed** from B-pkt in `k_apple_upper` (fix: `{27, 0xFE, ...}`)
- TransportRight has no confirmed visible Packet A or Packet B slot
- guided verify against Packet B candidates produced **no visible TransportRight light**
- Packet A pad slots `0..15` are pad rubbers
- Packet A scene-row slots `16..29` are already occupied
- Packet A slot `30` has already been tested locally and should not be treated as the default answer

**Working conclusion for now:**
- `logical[27]` is the software-side TransportRight signal
- the bridge correctly avoids mis-lighting Note Repeat
- there is still no proven separately addressable visible TransportRight LED in the
  current packet model

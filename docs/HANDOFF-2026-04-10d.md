## Confirmed Upper-Slot Remap (Apple Silicon)

Three upper selector-6 slots that were misrouted have been identified and corrected
via one-slot-at-a-time override experiments in `mk1-bridge/main.c`:

| logical slot | correct phys | button          | notes |
|-------------|-------------|-----------------|-------|
| logical[24] | phys[25]    | Erase           | Maschine lights Erase LED for Left/Back nav — intentional |
| logical[28] | phys[29]    | Record          | was routing to phys[28]=LCD-BL (wrong) |
| logical[30] | phys[26]    | Shift           | mode-dependent; only fires in certain app states |

These overrides are implemented via `k_apple_upper[]` in `forward_led()` and applied
after the main `k_hw_by_logical` linear remap loop.

## Key Finding: logical[24] = Erase carrier, not a "Left LED"

Every phys position tried for logical[24] that had a visible LED showed the Erase LED
(phys[4], [25], [27], [31]). Positions that showed nothing (phys[5], [17], [23]) were
dead for this slot. Conclusion: **logical[24] is the Erase LED carrier**. When the user
navigates Left/Back in Maschine, the software lights the Erase LED as a back/undo
state indicator — this is intentional software behavior, not misrouting.

The Left nav button's own directional LED (if any) is handled by the lower range:
`logical[8] → phys[5]` in `k_hw_by_logical`.
